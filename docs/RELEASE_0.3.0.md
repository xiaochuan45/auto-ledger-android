# 本地账本 0.3.0：多来源通知与支付身份分离

2026-10-27，用户确认目标为一个本地账本覆盖微信、支付宝和多个购物平台，不需要同步到其他记账软件，并暂停手机测试。研发先转向多来源架构，不要求用户继续安装 0.2.7 或再次支付。本轮对照开源方案的结论及固定来源见 [多应用调研](MULTI_APP_RESEARCH.md)。

本版 `0.3.0-prototype` / code10，沿用固定包名、签名和 Room schema1，覆盖 0.2.7 / code9，原有账单、去重和采集设置应保留，新购物来源默认关闭。APK 用于云端交付归档，当前无需手机安装或测试。

## 本轮实现

- 7 类来源：微信、支付宝、淘宝、京东、拼多多、美团（主应用和外卖两个包）、抖音；精确匹配共 8 个包，不扫描前缀相似应用。微信/支付宝页面范围不扩大，新增平台只有支付类通知入口。
- 来源应用、消费平台、实际支付渠道、分类分别处理；无法确认付款渠道时标未知，不把电商名当支付渠道，不凭平台推用途。
- 每个平台可独立选择，默认关闭，总开关与旧渠道选择仍生效。关闭来源立即取消待处理工作；仅开启平台也可检查/恢复通知连接，无需为此打开不想采集的支付应用。
- 按来源/规则版本/精确交易标题选择适配器，再有界读取必要通知字段；客服会话、汇总、促销不读正文，待付款/发货不记消费，关闭时不回扫旧通知。不引入联网、短信、截图、Root 或新增系统权限。
- 平台线索单独出现保留待核对；具有共同支付渠道交易号、金额一致时，可补已有未编辑账单缺失的平台，不能改金融字段或用户编辑。平台先到、支付后到时，共同支付交易号只留一笔，并用支付主证据核对确认。
- 普通订单号不作为支付交易号；未知渠道不建立强支付身份。同额不同交易不能合并，退款/转账等仍不自动计消费。
- 设置展示各平台开关及来源事件计数，账单展示未知渠道及辅助来源。旧版设置不会自动打开这些平台。

## 边界

本轮是多场景采集基础，**没有证明拼多多→微信、支付宝付款或平台免密在手机上已成功捕获**。系统不发交易通知、通知格式不同或只有不可读页面时仍无法自动获取；购物平台通知本身不承担自动确认消费的职责。已有无障碍文字适配仍有真机失败记录，不因为新增适配目录而宣称解决。

本机 OCR、账单导入、完整分类/统计/退款关联/加密备份继续后续实现。手机测试按用户要求暂停；不要求关闭支付保护或改变手机系统。
