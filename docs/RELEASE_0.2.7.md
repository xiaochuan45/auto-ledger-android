# 本地账本 0.2.7：可见子字段与请求结果归属

0.2.6 已安装启动，但真机仍无记录。最近一次小程序结构检查访问 1 个节点便因不可见停止，未见任何文字和四栏目；当前重新发起的请求检查 0，仅见主界面程序标识。旧版同时展示进程最近结构结果与当前请求计数，不能认定它们属于同一次请求。

源码确认一个有条件的漏读问题：不可见父节点会连同子树被跳过，可能漏掉其中可见字段。当前真机摘要未包含子节点数，无法证明真实微信属于这种结构，也无法证明微信完全没有提供文字。本版 `0.2.7-prototype` / code9 只修正可复现的遍历情况和结果归属，不宣称拼多多新付款自动记录已修复。

## 实现与边界

- 仅用户主动小程序详情：同包名、同窗口、非编辑/密码控件、在固定结构容器清单内且有子节点的不可见容器，可继续有界遍历。容器自身 text/contentDescription 不访问。每个子节点独立验证，可见字段才比较栏目或读值。
- 字段预筛选与正文读取使用相同的容器规则；正文额外逐节点核对同一窗口。不可见 TextView、未知控件、异包/异窗口、编辑或密码分支仍丢弃，不以父节点存在为字段授权。
- 四项必要栏目仍须来自可见节点；节点上限 512、请求 30 秒、最多 8 次且至少相隔 500ms 的事件检查保持不变；最多读取正文一次。不轮询、不截图、不扩到主界面和聊天，自动原生和普通网页保持旧可见性边界。
- 每次新请求清除旧结构结果；显示请求编号，结构摘要带归属请求及根可见性、根子节点数、仅遍历子节点的不可见容器数。不记录真实字段、任意控件文字或原文。
- 全部字段不可见、根没有子节点、没有合格入口事件时仍不产生账单。详情结果一律待核对，不自动计支出，不修改已有同交易号记录。不能用模拟树成功替代真实微信验证。
- 沿用固定包名、签名和数据库格式，直接覆盖 0.2.6，不卸载或清数据。无新增权限、联网、截图、全部窗口访问或后台原文日志。

## 手机验证

无需消费；覆盖安装，保持总开关、微信及无障碍开启并连接，结束只读检查。准备已有商家「交易详情」，回账本点「读取一次已有微信账单」，30 秒内切回详情并停留约 3 秒；必要时退出详情后重开同笔。

查看待核对。若仍为空，复制一次摘要，核对请求编号、窗口检查次数/阶段、检查归属、根可见性/子节点、四栏目标记及入口程序类型即可，不需要真实金额、时间、交易号或截图。如果只出现 `LauncherUI`，仍不读取主界面；根无子节点或没有可见字段也不会凭截图猜账。OCR 和账单导入尚未实现，是此路径无可读字段时的独立后续方案。

本地及云端验证进行中。新增回归覆盖不可见结构根下的可见虚构账单、不可见字段不能补齐栏目、整树不可见仍无正文、异包/窗口/敏感容器拒绝，以及新请求清除旧检查。虚构节点通过本机测试 Activity 的无障碍回调构造，不打开微信或拼多多，不代表用户手机已通过。
