# 本地账本 0.2.6：小程序入口事件即时检查

0.2.5 真机已安装，但用户反馈仍未记录：请求期间已有 `AppBrandPluginUI` 和 `LauncherUI`，超时、正文尝试 0 次，结构命中和解析 0。代码发现可复现的触发缺陷：已准入小程序先等待 1.5 秒，后续主界面或窗口事件可能取消未执行任务。旧摘要不包含事件顺序，不能断言这就是所有真机失败的唯一原因。

本版 `0.2.6-prototype` / code8，保持包名、固定签名和数据库格式；直接覆盖 0.2.5，不卸载或清数据。

## 实现与边界

- 服务实际使用的 `PaymentWindowCapture` 把窗口判断和触发连在同一条路径。用户主动请求的小程序入口一旦准入，立即检查当前根窗口和必要栏目，不再启动延迟小程序读取任务；后续主界面事件仍立即使会话失效，不读取主界面或聊天。
- 页面可能尚未加载完整：四栏目不足时只做有界栏目比较，不消耗正文读取；只等待后续合格事件，最多 8 次，至少相隔 500ms，请求总时限仍为 30 秒。无定时轮询，切换窗口不能重置次数，自动模式不读取小程序。
- 每次仍验证根包名和窗口 ID，最多 512 节点，仅固定短栏目比较；四项当前状态、支付时间、支付方式、交易单号齐全后，才消耗一次正文读取。用完、超时、取消、只读、断连或关闭开关后不能继续读取。
- 摘要和设置显示本次窗口检查次数及固定阶段：根窗口未提供、窗口不一致、栏目不足、达到上限或正文已尝试。计数不等于新增账单数；正文尝试 0 次但窗口检查大于 0 表示触发已执行，应看根窗口/栏目结果。
- 所有此入口新记录仍待核对，确认前不计支出；同交易号不修改已有记录。金额、支付时间与去重规则未放宽，未知字段不猜测。
- 未增加任何系统权限、截图、全部窗口读取、联网或原始账单日志。原生自动路径与普通网页延迟策略不变。真实截图和交易字段没有复制到仓库。

## 无消费的手机验证

1. 覆盖安装本版，保持总开关、微信和无障碍开启并连接，结束只读兼容性检查。
2. 微信准备好已有商家「交易详情」，回账本点「读取一次已有微信账单」，30 秒内切回详情，停留约 3 秒。必要时退出详情后重开同笔，不清后台、不付款。
3. 回账本看待核对，检查字段；相同交易号应复用原记录。没有记录就刷新并复制诊断，尤其本次小程序窗口检查次数/阶段、正文尝试次数、最近网页检查、四栏目存在标记和跳过原因。
4. 反馈无需真实金额、付款时间、商户、交易号或截图。本版是否能读取微信实际提供的字段仍待真机验证，不把自动化通过称为真实自动记账已修复。
