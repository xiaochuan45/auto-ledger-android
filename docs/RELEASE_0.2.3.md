# 本地账本 · 微信网页账单待核对识别 0.2.3-prototype

本版针对用户在微信 8.0.78 / Android API 36 看到的网页付款详情：它使用通用 `MMWebViewUI`，旧版精确付款 Activity 白名单不会命中。代码新增窄范围栏目检查与待核对识别，**并非拼多多付款实时自动入账已验证或已修复的声明**。构建、自动化、准确签名包和覆盖升级证据验证完成后补充，完成前不公开下载。

版本 `0.2.3-prototype` / code `5`，包名 `io.github.xiaochuan45.autoledger`，同一固定签名直接覆盖 `0.2.2` / code `4`；不要先卸载或清除数据。数据库格式未变。

## 本轮实现与边界

- 仅在微信指定网页容器事件建立当前窗口会话；不会把它当作已验证的付款原文来源。
- 先用系统节点查询查找固定七项栏目：当前状态、支付时间、支付方式、交易单号、商户单号、收单机构、账单服务；要求同一可见 WebView 内每项恰好一处。不会扫描普通网页全文，也不使用页面标题、成功字样或域名文本来冒充来源认证。
- 缺栏目、栏目只存在原生外层或另一 WebView、节点缺失时，直接跳过，不调用正文读取器。仅结构完整后才对该 WebView 有限读取；不读原生浏览器外壳、聊天、小程序、其他窗口或截图。
- 读取仍受 150 节点、4000 字符、敏感输入保护和完整性约束；仅这条网页路径的片段上限由 24 调为 48，通知及原生付款页面仍为 24。任何溢出或读取不完整都丢弃整次输入。
- 仅在完整结构及成功状态下，将状态表之前的明确负数金额视为支出候选；不把备注里的负数或正号收入当支出，不猜金额、商户或平台，不据商户标题判断分类。其他必要字段按已有明确标签解析。
- 所有这条网页路径的新记录**一律待核对，不自动计入支出**，显示来源未验证原因。共享容器和栏目结构不能证明网页来源真实性；用户核对字段并确认后才计入统计。若已有同交易号记录，仅登记去重收据，不另造一笔，也不修改该账单的金额、时间、状态或其他字段。网页来源单独标识，存储层再次强制新记录待核对。
- 新增固定的栏目未命中跳过原因与「微信网页账单结构命中」计数。它是检查次数，不是新增笔数。只读兼容性检查仍优先拦截，检查期间不进行栏目查询、读正文或入账。
- 不新增权限、不联网、不保存截图或账单全文。开发与测试只用虚构商户、金额、时间、订单号；用户截图与真实账单未提交仓库。

## 不消费的手机验证

1. 覆盖安装本版，保持总开关和微信渠道开启，确认两项服务连接。
2. **结束只读兼容性检查**，确认「检查未运行」。本轮是实际尝试识别，保持只读检查开启会按设计拦截。
3. 从微信钱包账单重新打开同一笔已有付款详情，停留几秒，再返回账本；不要清后台，无需再次消费或发送付款截图。
4. 查看「待核对」是否出现一项。已有交易号时应复用原记录；核对金额、实际付款时间和时间来源。商户或平台未知是允许结果，请勿凭空补全。未核对前无需确认入账。
5. 若没有结果，在设置刷新诊断，复制无账单原文的摘要。看网页结构命中、进入解析、完成与固定跳过原因；不要发送实际金额或交易号。
6. 在账本不做修改的情况下重开一次该详情，应仍只有同一项；这是测试旧详情读取与去重，不代表新付款、扫码、免密或后台扣费已经成功。

若字段不完整或不可读，请手动补记。若已手动补记且没有共同交易号，可能提示疑似重复，需用户核对，不能承诺自动关联。
