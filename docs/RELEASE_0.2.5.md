# 本地账本 0.2.5：主动读取商家页交易详情

微信 8.0.78 / Android API 36 的 0.2.4 真机反馈：一次请求超时、尝试 0 次，没有进入网页检查。随后只读摘要显示 `AppBrandPluginUI` 和 `LauncherUI`；用户确认查看的是商家资料页中的「交易详情」。这与先前适配的 `MMWebViewUI` 不同。当前失败停在窗口准入，不能据此推断微信字段不可读。

本版 `0.2.5-prototype` / code `7`，固定包名和签名，直接覆盖 0.2.4 / code6，数据库格式不变。不要卸载或清除数据。本版针对该入口的主动一次读取，**没有证明真实微信文字可读，也没有宣称新付款实时自动入账已修复**。

## 实现范围

- `AppBrandPluginUI` 仅在用户主动请求的 30 秒内成为候选。没有请求、请求用完、超时、取消、服务断开或只读检查运行时，不读取该入口；`LauncherUI` 及聊天仍不读取。不把小程序容器加入原生自动付款白名单。
- 在当前已验证微信包名、窗口 ID 的小程序窗口，最多检查 512 个节点的短栏目名称；必须找到当前状态、支付时间、支付方式、交易单号四项才调用正文读取。可处理原生/网页混合字段，普通小程序或栏目不足不会调用正文读取；不截图，不扩大系统权限。
- 小程序选择请求先消耗一次尝试，再做栏目检查；未匹配时也有固定原因及节点/四栏目存在标记。等待期间最多保留 6 个微信程序类型，超时后仍显示，以免下一次又只有「尝试 0 次」而没有入口线索。只保留本进程，不记录交易值或正文。
- 提取并复用窗口会话判断：限定同包、同窗口和有效期；少数系统子控件状态事件不再清掉已验证的待核对详情会话，不放宽原生自动确认路径。主界面事件、窗口切换、超时和清除会话仍失效。仅主动请求时，明确的小程序/网页宿主程序类型可从内容事件建立会话；普通 View 内容事件不能建立。
- 等待中的同一读取任务不再被连续内容事件无限推迟；小程序进入后留出短暂加载时间。无后台轮询。根包名和窗口变化仍立即丢弃；一次尝试后结束小程序会话。
- 商家资料区可能有很多导航行；仅这条主动小程序路径不再按标题行数拒绝金额，仍只接受状态表之前独立、明确的带符号金额。正号收入拒绝；多个不同金额、状态未知或金额不明不猜测。未知商户、平台保留未知，不按平台猜用途。
- 新记录一律待核对，不自动计支出；解析结果使用既有来源保护，已有同交易号账单不被修改，重开仍按交易号去重。所有原文及时丢弃，真实截图和数据未复制到仓库或测试。

## 手机只验证已有详情

1. 直接覆盖安装本版；总开关、微信渠道和无障碍保持开启，结束只读兼容性检查。
2. 在微信准备好商家页的「交易详情」。回账本点「读取一次已有微信账单」，30 秒内切回该详情，停留约 3 秒；必要时退出详情再重新打开，让宿主窗口产生事件。不要清后台，无需消费。
3. 回账本看待核对，核对字段是否正确；已有相同交易号应复用原记录。未核对前无需确认。手动补记缺共同交易号时仍需检查重复。
4. 刷新并复制摘要，保留一次请求状态/尝试数、请求期间程序类型、最近网页检查、详情结构、节点和栏目存在标记、跳过原因。不要发送真实金额、时间、商户、订单号或截图。

如果尝试已发生但系统没有提供必要交易字段，就根据新的结构结果转离线 OCR 或账单导入；这两项仍未实现。本版不要求再次支付，不因没有结果就继续扩大到聊天或所有小程序读屏。
