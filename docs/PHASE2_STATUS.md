# 第二阶段：自动识别小样

版本 `0.2.0-prototype`，versionCode `2`，包名 `io.github.xiaochuan45.autoledger`。记录日期：2026-10-16。

本阶段源代码已实现，最终构建、系统矩阵和交付验证进行中。此文档只记录已有证据；没有用户手机测试证据的支付场景全部待验证。

## 实现范围

- 微信、支付宝必要付款页面与非会话交易通知的本地规则识别；采集默认关闭，可控制渠道和系统权限。
- 明确成功及实付金额才确认；金额、状态或交易身份有歧义进入待核对。余额、收入、失败、待支付及不完整信息不冒充消费。
- 平台、支付渠道、分类独立存储；未知信息留空；时间标注为支付、识别或用户填写。
- Room 本地存储，强渠道交易号及来源收据持久去重；弱相似只提示待核对，不强行合并。支持显式保留另一笔或合并重复、手动补记、编辑、删除撤销。
- 统计仅提供已确认消费总额；退款、转账、充值、提现本阶段保持待核对，不计入消费。完整周期统计、分类规则、退款关联、导入导出和加密备份属于后续阶段。
- 状态页区分授权与连接，显示不含原文的本次进程诊断计数，提供恢复入口。权限或状态正常不代表所有后台场景可捕获。

## 兼容与隐私边界

目标是通用 Android 8.0 及以上，不绑定手机品牌。API 26/35 模拟器验证通过后会分别记录结果；不能将模拟器推广为厂商系统或所有支付版本通过。

仅两个付款应用进入过滤。为避免聊天冒充支付通知，会拒绝 conversation、MessagingStyle、people 等会话消息；这也可能漏掉微信实际使用会话形式发送的官方支付通知。无障碍使用精确付款 Activity 清单；通用聊天、Launcher 和网页页面不读取。类名、页面结构及通知格式需真实手机继续适配。

超过字符、片段或节点上限、读取不完整的输入整体丢弃，不用截断后剩下的“成功”字样猜测交易。没有交易号及付款时间的页面通常进入待核对。缺少共同交易号的相似来源不承诺完全自动关联；连续同额真实付款仍保留可独立确认。

应用不申请联网、存储或前台服务权限。两项采集服务分别受系统 BIND 权限保护；系统通知使用权和无障碍需要用户主动开启。仅必要结构化字段与不可逆收据哈希进入数据库，不记录原始屏幕、通知、聊天或异常全文。自动云备份与设备迁移数据域均排除。

## 签名与更新

与第一阶段无账单的 `.preview` 安装包并列安装。本版使用固定私密签名；公开证书指纹保存在 [config/signing-certificate.sha256](../config/signing-certificate.sha256)。初始化和签名脚本会核对指纹；密钥不可用时拒绝自动生成替代密钥。

私钥和口令仅保存在本次受管云端仓库外的私有目录，没有提交 GitHub、写入日志或附在发布包中。当前 GitHub 连接不支持 Secrets 管理，密钥尚未配置到 GitHub Secrets 或其他持久密钥服务；更换或删除云端环境前需要安全迁移和备份。当前方案只能在原密钥可用时继续同签名更新，不承诺密钥自动跨环境恢复。

最终交付验证会对准确的签名 APK 执行仪器测试，并在两次独立测试之间真正 `adb install -r` 安装同签名更高版本，核对虚构账单及去重信息保留。这不代表未来数据库 schema 迁移已验证。
