# 本地账本 · 只读兼容性诊断 0.2.2-prototype

本版用于定位「服务已连接，但付款没有进入解析」的问题，**没有宣称已适配拼多多微信付款**。本轮编译、最终 APK 与覆盖升级验证完成后再公开下载。

版本 `0.2.2-prototype` / code `4`，包名 `io.github.xiaochuan45.autoledger`；直接覆盖已安装的同签名 `0.2.1` / code `3`，不要先卸载或清除数据。

## 已知真机事实

用户在 `0.2.1` 上再次使用拼多多 → 微信付款，仍未自动记录。付款后截图的通知和无障碍均已授权、已连接；旧诊断为进入解析 0、完成 0、异常 0，恢复请求 2 次。截图不能证明付款时始终连接，也不能证明系统没发事件：旧计数发生在页面与通知筛选之后。

## 本轮内容

- 分开显示已选渠道的系统窗口事件、通知事件、支持窗口、进入解析、处理完成、跳过和异常计数，避免把过筛计数称为所有监听事件。
- 跳过原因只有固定分类，包括页面不支持、会话通知、窗口不可用、敏感保护及解析无交易证据；不会保存通知标题、正文或付款原文。
- 用户主动开始「只读兼容性检查」后，在本次进程最多运行 5 分钟，暂停自动记录；不读付款文字或截图、不新增检查账单。手动补记仍可用。结束、超时或进程重启后按原采集开关工作。
- 检查仅在内存保留最多 6 个微信或支付宝的规范程序类型名；仅开启的渠道可产生事件。类型名用于适配页面，不包含交易信息。用户可清除结果或主动复制无账单原文的诊断摘要。
- 不新增权限，不扩大读取付款原文的页面白名单，不放宽会话通知过滤，不修改解析、分类或数据库格式。

## 不消费的手机检查步骤

1. 安装本版，确认总开关、微信渠道及两项系统服务状态。
2. 设置中点「开始只读检查（5 分钟）」，确认显示「检查中 · 暂停自动记录」。
3. 直接切到微信：我 → 服务（旧版可能叫支付）→ 钱包 → 账单，打开这次**已有付款**的详情，然后回到本应用。期间不要清后台；无需重新消费，也不要发送真实付款页面。
4. 点「刷新检查结果」，结束检查，再点「复制无账单原文的诊断摘要」，把摘要发到开发对话。若程序类型结果为空，也如实保留。

检查不会补抓之前漏掉的账单。5 分钟或进程结束后诊断停止，类型结果仅存在当前进程内；清除结果会删除这些类型名。
