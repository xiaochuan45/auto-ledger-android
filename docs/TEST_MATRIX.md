# 测试矩阵与证据要求

基线：2026-10-16。本文定义需要验证的项目，不表示项目已通过。初始状态全部为「待验证」；执行后应在版本交付记录中附结果和必要证据。

## 记录规则

- **代码已实现**：列源码位置或提交；仅说明实现存在。
- **模拟或自动化通过**：列执行命令、环境、虚构或脱敏样本、断言及结果。
- **用户手机真机通过**：记录 APK 版本、手机型号、Android/系统版本、相关应用版本、测试日期和场景结果。
- 构建通过不能替代安装启动；模拟文本解析通过不能替代真实支付场景；服务状态正常不能替代跨夜验证。
- 无法读取、未发生、不适用、失败、待验证分别记录，不能统称通过。来源可读与金额正确、无重复、时间正确也应分开检查。
- 自动化、日志和仓库只放虚构或脱敏数据。真机反馈使用结构化结果即可，不上传完整真实账单、通知全文、聊天、验证码或截图中的敏感信息。

## 真机反馈最小模板

每个场景记录以下内容，避免上传敏感原始数据：

```text
测试日期：
APK 版本 / 源码提交：
手机型号：一加 Ace 5
Android / 系统版本：
相关应用及版本：
场景编号 / 平台 / 支付渠道：
应用当时状态：前台 / 后台 / 锁屏；已放置时长：
必要权限及系统电池设置状态：
结果：通过 / 失败 / 不可读 / 未发生 / 待验证
记录笔数是否正确：
实付金额是否正确：
付款时间或识别时间标注是否正确：
平台、渠道、分类是否正确或明确未知：
是否重复 / 漏记 / 进入待核对：
恢复操作及结果：
已脱敏的补充说明：
```

版本交付时附已执行测试的结果表，逐层列明证据。未执行项继续保留待验证；没有用户手机证据的场景，不得标为真机通过。
