# 自动识别小样：手机设置与验证

最新版本 `0.2.6-prototype` / versionCode `8`，包名 `io.github.xiaochuan45.autoledger`，最低 Android 8.0 / API 26。不绑定品牌；不同系统和支付应用版本需分别验证。

用户在微信 8.0.78 / API 36 的商家页「交易详情」由 `AppBrandPluginUI` 承载。0.2.5 请求期间虽看到小程序入口，仍超时、正文尝试 0 次。0.2.6 去掉小程序 1.5 秒延迟：准入事件当下检查当前根窗口和四栏目，栏目齐全才读正文一次；栏目不足可随后续事件有限检查，不轮询。主界面和聊天仍拒绝，所有详情新记录待核对。旧摘要无法证明具体逐事件取消原因，本版不宣称真机字段可读或自动记录已修复。依据和证据见 [本版说明](RELEASE_0.2.6.md)。

## 本次只验证已有交易，不消费

1. 下载 [本版 APK](https://github.com/xiaochuan45/auto-ledger-android/releases/download/prototype-v0.2.6/auto-ledger-prototype.apk)，直接覆盖旧版，不要卸载或清数据。
2. 确认总开关、微信渠道和无障碍已开启并连接，结束只读兼容性检查；在微信准备好商家页「交易详情」。
3. 回账本设置点「读取一次已有微信账单」，30 秒内切回同一详情并停留约 3 秒。若需要重新产生宿主窗口事件，可退出详情后重开同一笔；不清后台、不付款。
4. 回账本看「待核对」，核对字段；已有相同交易号应复用原记录。未核对前无需确认，没有共同交易号的手工补记仍需检查重复。
5. 刷新并复制诊断摘要：保留版本、一次请求状态/尝试数、本次请求程序类型、小程序窗口检查次数/阶段、最近网页检查、详情结构、节点和四栏目存在标记，以及进入解析和跳过原因；不要发真实金额、时间、商户、交易号或截图。

本次小程序最多检查 8 次窗口，至少相隔 500ms，只由后续合格事件触发；四栏目齐全后才消耗一次正文读取。栏目不足或根窗口不可用时，正文尝试为 0 也可能已经执行窗口检查，应看检查次数和固定阶段。达到 8 次或超时后不再检查，切换窗口不重置预算。检查 0 次时再看请求期间程序类型和权限/窗口跳过原因，无需再次消费。已选渠道窗口事件和支持窗口不是笔数；支持窗口仅指原生精确付款类型，小程序成功不要求该值增加。微信详情结构命中也不是新增笔数。

请求结束、到期、服务断开、关闭开关、只读检查或进程重启后，不继续小程序读取。小程序必须四项栏目齐全才调用正文读取，普通页面或只有成功字样不会生成账单。无联网、截图、后台轮询或旧通知回扫。网页来源和小程序容器都不能认证付款，所以结果一律待核对，确认前不计支出，也不修改已有同交易号的账单。

如果已到达检查，但系统没提供必要交易字段，下一条独立路线是本机 OCR 或账单导入，当前均未实现；过滤、超限或缺节点时先按对应原因排查，不把它们笼统当作微信没有文字。字段无法读取时仍可手动补记。

## 可选：只看程序类型

需要排查新页面类型时，可主动开始最多 5 分钟的只读兼容性检查；期间暂停自动记录，仅保留本次进程最多 6 个程序类型名，可结束或清除。结束、超时或进程重启后按原开关采集；不会补抓旧通知或交易。当前验证步骤需要该模式关闭。

## 安装与更新

只安装公开 Release 的 `auto-ledger-prototype.apk`；不要安装普通 CI 的调试包或 `verification-*` 测试附件。系统询问时，为当前浏览器或文件管理器允许安装未知应用，完成后可关闭该来源的安装权限。

同包名、同签名且版本号更高时直接覆盖安装，保留本地数据。准确公开旧 0.2.5 / code 7 → 本版 code 8 的模拟器覆盖更新证据见本版说明，保留虚构账单、去重标识及总/渠道开关；这不等于用户手机升级已实测。第一阶段 `.preview` 是并列应用，没有自动记账。

本阶段尚无导出或加密备份，请保留其他账目来源，不把小样作为唯一账本。

## 开启与恢复自动记账

采集默认关闭。首次使用时，进入设置，开启自动记账总开关及需要的微信、支付宝渠道，再授予系统通知使用权并启用无障碍服务。后续由系统通知或受支持付款窗口事件触发，不要求账本界面一直打开，也不循环读屏。

通知项分开提供「打开通知权限设置」与「尝试恢复通知监听」。已授权但未连接时才尝试恢复，以真实连接回调为准；点击成功不代表服务已经连接。恢复请求受总开关、渠道和授权约束，30 秒节流，每个断开周期自动尝试一次；不读取旧通知，不补记旧交易。权限状态可手动刷新。

某些 Android 13 及以上系统若明确提示「受限制的设置」，可在系统应用信息右上角菜单查找「允许受限制的设置」，确认安装来源后再授权；入口以系统实际提示为准。

离开界面或切换应用与清理后台、系统强行停止不同。可按手机实际设置允许后台活动；部分系统可在最近任务锁定应用，但不保证绕过厂商限制。通知恢复不能绕过强行停止或省电限制。无可读交易通知或受支持页面时无法捕获，服务已连接也不保证所有场景可识别。

## 账单检查和纠正

- 已确认消费：受支持原生页面或交易通知的状态与实付金额明确时自动保存；网页新记录始终先待核对。分类初始为“未分类”。平台、支付渠道和分类分别显示；没有可靠商户或平台时显示“未知”。
- 待核对：金额、状态、历史页面或重复关联存在歧义时，不计入已确认支出。打开明细后核对真实付款，可改金额、时间、商户、平台、分类和备注，再确认。
- 同一交易号、同一来源事件重复时复用已有记录。缺少共同交易号的跨来源相似记录不会凭金额和时间自动合并，可能进入待核对；确认为同笔可“合并到原账单”，确认为另一笔可“保留为独立交易并核对”。
- 时间标注为付款时间、识别时间或用户修改时间；只有识别时间时不要将其当作支付平台的准确付款时间。
- 可从账单页右下角手动补记。删除后可在底部提示中撤销；去重所需的最小结构化标识仍用于阻止已删交易被相同来源重新导入。
- 退款、转账、充值和提现本阶段保留待核对，不自动作为消费；退款到账关联和抵减统计尚未实现，不要为了清除待核对而把退款改成支出。

## 没有自动记录时

检查总开关、渠道、授权和实际连接；不要反复付款或授权无关应用。恢复不会补抓旧交易。仍漏记时手动补记，保持只读检查关闭，反馈本次运行的固定诊断摘要；没有可读信息的场景无法自动捕获。账单导入、退款关联、完整分类统计及加密备份尚属后续工作。
