# 自动识别小样：权限、范围与后续验证

**2026-10-27，按用户要求暂停手机真机测试。当前无需安装、再次消费、提供真实账单或继续执行旧版诊断步骤。** 开发与云端虚构数据验证继续；本页记录以后恢复测试时的范围，不是本轮要求用户执行的任务。

当前云端归档 `0.3.0-prototype` / code10，包名 `io.github.xiaochuan45.autoledger`，最低 Android 8.0。固定签名直接覆盖 0.2.7，不卸载或清数据；安装、签名、回归及公开下载实际证据见 [0.3.0 说明](RELEASE_0.3.0.md)。

## 多场景当前范围

| 来源应用 | 本轮入口 | 如何计账 | 真机状态 |
|---|---|---|---|
| 微信 | 原受限付款页面/详情、非聊天形式交易通知 | 明确成功且实付明确的支付主证据可确认；通用详情仍待核对 | 拼多多→微信等此前未通过；本轮暂停 |
| 支付宝 | 原受限付款页面、非聊天形式交易通知 | 明确成功且实付明确的支付主证据可确认 | 本轮暂停，未证明可用 |
| 淘宝 / 京东 / 拼多多 / 美团（含外卖）/ 抖音 | 精确包名及交易标题筛选的通知；各自默认关闭 | 辅助核对；共同支付交易号及同金额时可补缺失平台，不改金额/状态/时间/商户/分类/用户编辑 | 新增代码，未实测通知是否发出、标题和字段是否匹配 |

源应用不是支付账户：在拼多多付款可能用微信、支付宝或其他渠道，没有明确证据时标未知。普通订单号不是微信/支付宝的支付交易号，不能凭同金额/时间或订单号自动把两笔账合并。平台名不决定消费用途，分类保持独立。

无通知、平台只发发货/促销/待付款、字段不可读或格式未适配时，无法自动捕获。没有可用字段不能靠重复授权补出信息。旧 0.2.7 的不可见容器修复和单次读取不等于新付款自动记录已经成功；历史事实见 [阶段记录](PHASE2_STATUS.md)。

## 后续恢复使用时的开关与权限

采集总开关默认关闭，系统权限不会自动开启识别。微信、支付宝保持各自开关；五类平台通知需单独选择，默认关闭，更新不自动扩大读取。总开关关闭时全部停止。

平台开关允许读取该应用受限的交易通知；付款渠道能明确解析时，还服从微信/支付宝渠道开关，关闭该渠道会跳过保存并显示固定原因。未知付款渠道按已选平台来源进入待核对，不猜账户。只开启平台也能检查或尝试恢复通知监听，不必额外开启其他来源。

通知使用权、服务是否已连接与是否成功识别，是三个不同状态。提供系统设置入口与「尝试恢复通知监听」，以真实系统连接回调为准；恢复不回扫旧通知、不补抓此前漏记账单，也不绕过强行停止或系统省电。无障碍仍只配置微信和支付宝，本轮没有读取电商页面或扩大截图/全部窗口权限。

不同品牌可在系统应用管理检查后台活动与电池策略，入口以手机实际为准；不要求关闭支付安全保护。Android 若明确提示「受限制的设置」，可在确认安装来源后按系统引导授权，当前不要求执行。

## 账单检查及纠正

- 观察到通知/页面事件不等于产生账单，服务连接不保证所有支付场景可读。诊断保留固定来源应用计数、原因和整数，不保留真实通知或整屏正文。
- 支付主证据明确成功、实付金额明确时可确认消费；网页与平台辅助证据保留待核对，不计支出；未知渠道显示未知。
- 平台线索先到、支付主证据后到：共同支付交易号关联，核对金额后只留一笔，并优先使用支付方商户。支付先到、平台后到：仅补未编辑账单缺失的平台，不能改金融字段。
- 不同强支付交易号、同额真实付款独立保留。缺少共同支付身份的跨来源信息不自动合并，用户以后核对或补记，避免重复计数。
- 日期标为实际支付时间、识别时间或用户修改时间；不把下单时间冒充付款时间。
- 可手动补记和编辑金额、时间、平台、渠道、分类、备注；未知渠道可保留未知。删除支持撤销，最小去重标识保留以避免历史重复识别重建已删账单。
- 退款、转账、充值和提现暂留待核对，不自动作为消费。退款到账关联、周期净支出、导入导出与加密备份尚未完成，不把本小样作为唯一账目来源。

## 恢复真机验证后才执行的场景

优先结合日常自然发生的付款，不为测试专门消费，不上传金额、时间、商户、交易号、整屏文字或截图。后台扣费要有独立可读来源，不能用旧详情页面成功替代后台捕获。

| 场景 | 后续验收重点 |
|---|---|
| 微信 / 支付宝扫码和被扫码 | 实际成功、优惠后金额、付款时间和支付渠道 |
| 拼多多 / 淘宝 / 京东 / 美团 / 抖音购物 | 消费平台与付款账户分别识别，不凭应用名推分类 |
| 平台内免密、会员续费及后台扣费 | 实际收到的通知类型与金额；没有可读来源明确漏记 |
| 平台与支付通知双来源 | 两种到达顺序只记一笔，缺共同身份不猜关联 |
| 连续两笔同金额 | 不误合并；不同交易号独立，信息不足时待核对 |
| 失败 / 取消 / 待付款 / 发货 / 促销 | 不新增确认消费 |
| 退款申请、全额/部分到账 | 不把申请当到账，不重复计消费，关联能力尚未完成 |
| 清理后台、锁屏、跨夜、重启与恢复 | 分别记录服务状态、漏记及运行时长；不宣称永不漏记 |
| 更新 | 固定签名覆盖并保留账单、去重和原开关，新增来源默认关闭 |

若以后无法读取，下一条独立路线是本机 OCR 或微信/支付宝文件导入，两者目前未实现。先验证离线模型/格式、瞬时处理、去重及依赖权限；不以扩大聊天读取或猜测付款解决。

完整验收矩阵见 [TEST_MATRIX.md](TEST_MATRIX.md)。用户恢复真机测试前，不重复请求测试反馈。
