# 自动识别小样：手机设置与验证

最新版本 `0.2.4-prototype` / versionCode `6`，包名 `io.github.xiaochuan45.autoledger`，最低 Android 8.0 / API 26。不绑定品牌；不同系统和支付应用版本需分别验证。

用户在微信 8.0.78 / Android 16（API 36）的付款详情使用 `MMWebViewUI`。0.2.3 真机网页栏目命中与解析均为 0，14 次结构拒绝；并非权限已连接就能记账。本版修正合并行、可选栏目及重复节点，增加分层诊断与主动一次读取。**新付款实时自动记录仍未通过真机验证**。所有网页新记录仍需核对，不计入已确认支出，已有相同交易号的账单不被修改。依据见 [GitHub 调研](WECHAT_ACCESSIBILITY_RESEARCH.md)，证据见 [本轮说明](RELEASE_0.2.4.md)。

## 本次只验证已有付款，无需消费

1. 下载 [本版 APK](https://github.com/xiaochuan45/auto-ledger-android/releases/download/prototype-v0.2.4/auto-ledger-prototype.apk)，直接覆盖旧版，不要卸载或清除数据。
2. 设置中确认总开关、微信渠道开启，两项服务已授权并已连接；**结束「只读兼容性检查」**。
3. 点「读取一次已有微信账单」。30 秒内切到微信，先退出详情，再重新打开同一笔已有付款，停留几秒后回到账本；不要清后台，无需支付。
4. 查看「待核对」是否出现一项；已有相同交易号时应复用原记录。检查金额、付款时间及时间来源是否正确，未知字段允许留空。未核对前无需确认。
5. 回设置刷新诊断，复制「无账单原文的诊断摘要」。保留「一次微信读取」「最近网页检查」、节点和过滤计数、必要栏目四项、进入解析与跳过原因；不用发送实际金额、时间、交易号或付款截图。

一次请求仅用于一个当前已验证微信网页窗口，结束、到期、服务断开、关闭开关或开始只读检查后不继续；没有截图、常驻轮询或自动回扫。自动模式仍先做有限栏目分类；主动一次读取允许跳过结构预筛选，但仍需最小字段且只能生成待核对。

摘要中的「支持窗口」仍仅计精确原生付款类型；「微信网页账单结构命中」表示自动结构通过次数，不是新增账单数。主动一次读取可能在结构未全齐时进入解析，不能只凭命中 0 判断请求没有执行。计数为本进程累计，最近一次只读跳过不代表复制时仍在检查。

若检查完整、没有超限/缺节点/过滤且网页无文字，一次读取也没有字段，就停止继续试栏目规则；下一条独立路线是本机 OCR 或账单导入，目前均未实现。出现规则缺项、过滤或超限则按对应原因排查，不能笼统归因于微信限制。

若先前已手动补记但缺少共同交易号，不能承诺自动关联，请勿为测试确认重复消费。可读后再重开同一详情验证去重；它不代表新付款、免密或后台扣费通过。字段无法读取时可手动补记。

## 可选：只看程序类型

需要排查新页面类型时，可主动开始最多 5 分钟的只读兼容性检查；期间暂停自动记录，仅保留本次进程最多 6 个程序类型名，可结束或清除。结束、超时或进程重启后按原开关采集；不会补抓旧通知或交易。当前验证步骤需要该模式关闭。

## 安装与更新

只安装公开 Release 的 `auto-ledger-prototype.apk`；不要安装普通 CI 的调试包或 `verification-*` 测试附件。系统询问时，为当前浏览器或文件管理器允许安装未知应用，完成后可关闭该来源的安装权限。

同包名、同签名且版本号更高时直接覆盖安装，保留本地数据。准确公开旧 0.2.3 / code 5 → 本版 code 6 的模拟器覆盖更新证据见本版说明，保留虚构账单、去重标识及总/渠道开关；这不等于用户手机升级已实测。第一阶段 `.preview` 是并列应用，没有自动记账。

本阶段尚无导出或加密备份，请保留其他账目来源，不把小样作为唯一账本。

## 开启与恢复自动记账

采集默认关闭。首次使用时，进入设置，开启自动记账总开关及需要的微信、支付宝渠道，再授予系统通知使用权并启用无障碍服务。后续由系统通知或受支持付款窗口事件触发，不要求账本界面一直打开，也不循环读屏。

通知项分开提供「打开通知权限设置」与「尝试恢复通知监听」。已授权但未连接时才尝试恢复，以真实连接回调为准；点击成功不代表服务已经连接。恢复请求受总开关、渠道和授权约束，30 秒节流，每个断开周期自动尝试一次；不读取旧通知，不补记旧交易。权限状态可手动刷新。

某些 Android 13 及以上系统若明确提示「受限制的设置」，可在系统应用信息右上角菜单查找「允许受限制的设置」，确认安装来源后再授权；入口以系统实际提示为准。

离开界面或切换应用与清理后台、系统强行停止不同。可按手机实际设置允许后台活动；部分系统可在最近任务锁定应用，但不保证绕过厂商限制。通知恢复不能绕过强行停止或省电限制。无可读交易通知或受支持页面时无法捕获，服务已连接也不保证所有场景可识别。

## 账单检查和纠正

- 已确认消费：受支持原生页面或交易通知的状态与实付金额明确时自动保存；网页新记录始终先待核对。分类初始为“未分类”。平台、支付渠道和分类分别显示；没有可靠商户或平台时显示“未知”。
- 待核对：金额、状态、历史页面或重复关联存在歧义时，不计入已确认支出。打开明细后核对真实付款，可改金额、时间、商户、平台、分类和备注，再确认。
- 同一交易号、同一来源事件重复时复用已有记录。缺少共同交易号的跨来源相似记录不会凭金额和时间自动合并，可能进入待核对；确认为同笔可“合并到原账单”，确认为另一笔可“保留为独立交易并核对”。
- 时间标注为付款时间、识别时间或用户修改时间；只有识别时间时不要将其当作支付平台的准确付款时间。
- 可从账单页右下角手动补记。删除后可在底部提示中撤销；去重所需的最小结构化标识仍用于阻止已删交易被相同来源重新导入。
- 退款、转账、充值和提现本阶段保留待核对，不自动作为消费；退款到账关联和抵减统计尚未实现，不要为了清除待核对而把退款改成支出。

先完成上面的已有付款详情读取检查，保持只读兼容性检查关闭。后续测试结合正常日常付款逐项验证，无需专门消费；不上传真实金额、交易号、完整账单、原始通知、聊天或验证码。

## 没有自动记录时

检查总开关、渠道、授权和实际连接；不要反复付款或授权无关应用。恢复不会补抓旧交易。仍漏记时手动补记，保持只读检查关闭，反馈本次运行的固定诊断摘要；没有可读信息的场景无法自动捕获。账单导入、退款关联、完整分类统计及加密备份尚属后续工作。
