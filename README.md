# auto-ledger-android

面向 Android 8.0 及以上手机的本地自动记账工具，追求简洁、实用、易用，不绑定手机品牌。首次真机设备为一加 Ace 5，具体 Android 与系统版本待实机确认。

## 当前进度

第二阶段识别小样 `0.2.0-prototype` 代码已实现：本地交易识别、持久去重、待核对、手动补记与修改、删除撤销、权限状态及诊断。JVM 46 项、Python 8 项测试、Lint 及本地固定签名 APK 审计已通过；API 26/35 模拟器验收仍有一项日期断言正在修正，尚未全部通过。最终验证、CI 和发布结果确认后更新下载链接；**当前下方附件仍是第一阶段安装预览，不含自动记账功能**。详见 [第二阶段记录](docs/PHASE2_STATUS.md) 和 [手机权限与测试步骤](docs/PHASE2_TESTING.md)。

第一阶段的云端构建、Lint、实际 APK 审计，以及 Android 15 模拟器启动和三个页面导航测试已通过（2 项测试，0 失败）。[安装预览版已发布](https://github.com/xiaochuan45/auto-ledger-android/releases/tag/preview-38843855896-1)，用户已反馈在一加 Ace 5 安装、启动正常，具体系统版本与其他细项待补充。

**[下载 APK：本地账本·预览 0.1.0-preview](https://github.com/xiaochuan45/auto-ledger-android/releases/download/preview-38843855896-1/auto-ledger-preview.apk)**，约 9.3 MB，最低 Android 8.0。安装方法、签名限制和校验值见 [云端编译与手机安装](docs/BUILD_AND_INSTALL.md)。

## 自动记账如何触发

以下说明适用于第二阶段小样。采集默认关闭；用户在设置里一次开启自动记账总开关和所需的微信/支付宝渠道开关，按引导授予通知使用权并启用无障碍服务。之后系统出现可读交易通知或受支持付款页面事件时，会唤起对应服务进行本地识别；无需让账单应用界面一直开着，也不会循环读屏。

系统需要允许相关服务后台运行。强行停止应用、撤销权限或厂商省电限制可能导致中断，可到设置状态页检查授权与连接，并按入口恢复。没有可读取的付款页面，也没有可读交易通知时，无法自动捕获；当前可手动补记，账单文件导入将在后续实现。后台扣费及不同支付应用版本的实际覆盖范围需逐项真机验证。

## 产品边界

- 识别、分类和存储在手机本地完成，不需要后端，不使用云端大模型。
- 应用不申请联网权限，不接广告、统计或云端日志；交付前检查最终 APK。
- 消费平台、支付渠道和消费分类分别记录；未知信息不编造。
- 付款成功且实付金额明确才自动入账；金额或状态不明进入待核对。
- 交易通知、无障碍页面等来源的覆盖能力以实机验证为准；没有可读来源时提供导入或补记办法。
- 云端开发和测试只使用虚构、脱敏数据，真实账单不提交到仓库。

## 开发方向

原生 Kotlin、Jetpack Compose，已使用 Room 本地存储账单。使用 Gradle Wrapper 和 GitHub Actions 在云端编译，不依赖个人电脑。

先走通「云端构建 → APK 下载 → 手机安装启动」，再交付自动识别小样，随后依据真机结果完善功能。每轮明确区分「代码已实现」「模拟或自动化测试通过」「用户手机真机实测通过」。
