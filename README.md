# auto-ledger-android

面向 Android 8.0 及以上手机的本地自动记账工具，追求简洁、实用、易用，不绑定手机品牌。首次真机设备为一加 Ace 5，具体 Android 与系统版本待实机确认。

## 当前进度

最新 `0.2.3-prototype` 增加微信网页账单的窄范围待核对识别：先在指定网页容器内有界比较短栏目，完整匹配后才读取字段。**网页新记录一律待核对，确认前不计入支出**；结构不是来源认证，也不会修改已有相同交易号的账单。微信 8.0.78 / Android 16 的实际页面可读性仍待用户验证，尚未证明拼多多付款实时自动入账已修复。

**[最新 APK：本地账本 0.2.3-prototype](https://github.com/xiaochuan45/auto-ledger-android/releases/download/prototype-v0.2.3/auto-ledger-prototype.apk)**，约 7.16 MB，最低 Android 8.0；[发布页与证据](https://github.com/xiaochuan45/auto-ledger-android/releases/tag/prototype-v0.2.3)。直接覆盖旧版，不要卸载或清除数据。验证步骤：结束只读兼容性检查 → 微信退出并重新打开已有付款详情 → 回账本查看待核对 → 重开详情检查不重复，无需再次消费；详见 [手机步骤](docs/PHASE2_TESTING.md)。

## 自动记账如何触发

以下说明适用于第二阶段小样。采集默认关闭；用户在设置里一次开启自动记账总开关和所需的微信/支付宝渠道开关，按引导授予通知使用权并启用无障碍服务。之后系统出现可读交易通知或受支持付款页面事件时，会唤起对应服务进行本地识别；网页账单新记录仍需核对来源和字段，确认前不计入支出；无需让账单应用界面一直开着，也不会循环读屏。

离开账本界面不等于清理后台或强行停止。系统需要允许相关服务后台运行；强停、撤销权限或厂商省电限制可能导致中断，应用不能保证绕过。已授权但未连接时，可到设置点“尝试恢复通知监听”，以实际连接回调为准。没有可读取的付款页面或交易通知时无法捕获，当前可手动补记，账单文件导入将在后续实现。后台扣费及不同支付应用版本的覆盖范围需逐项真机验证。

## 产品边界

- 识别、分类和存储在手机本地完成，不需要后端，不使用云端大模型。
- 应用不申请联网权限，不接广告、统计或云端日志；交付前检查最终 APK。
- 消费平台、支付渠道和消费分类分别记录；未知信息不编造。
- 付款成功且实付金额明确才自动入账；金额或状态不明进入待核对。
- 交易通知、无障碍页面等来源的覆盖能力以实机验证为准；没有可读来源时提供导入或补记办法。
- 云端开发和测试只使用虚构、脱敏数据，真实账单不提交到仓库。

## 开发方向

原生 Kotlin、Jetpack Compose，已使用 Room 本地存储账单。使用 Gradle Wrapper 和 GitHub Actions 在云端编译，不依赖个人电脑。

先走通「云端构建 → APK 下载 → 手机安装启动」，再交付自动识别小样，随后依据真机结果完善功能。每轮明确区分「代码已实现」「模拟或自动化测试通过」「用户手机真机实测通过」。
