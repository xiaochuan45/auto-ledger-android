# auto-ledger-android

面向 Android 8.0 及以上手机的本地自动记账工具，追求简洁、实用、易用，不绑定手机品牌。首次真机设备为一加 Ace 5 / Android 16（API 36）；厂商系统细版按需确认。

## 当前进度

最新 `0.3.0-prototype` 转向多来源采集：微信、支付宝，以及淘宝、京东、拼多多、美团（含外卖）、抖音分别按来源适配，消费平台、实际支付渠道与分类分开记录。购物平台新增独立通知开关，默认关闭；没有明确支付渠道时保留未知。依据见 [公开实现调研及架构](docs/MULTI_APP_RESEARCH.md)。**多个来源的代码入口已实现，不能视为这些软件和支付场景已真机适配成功；0.2.x 拼多多→微信的真实失败记录保留。**

**手机测试按用户要求暂停（2026-10-27）。** 本轮仅做虚构通知、云端设备回归与覆盖升级，不需要用户安装、消费或提供真实账单。后续 APK 仅用于交付归档：[0.3.0 发布页](https://github.com/xiaochuan45/auto-ledger-android/releases/tag/prototype-v0.3.0) / [APK](https://github.com/xiaochuan45/auto-ledger-android/releases/download/prototype-v0.3.0/auto-ledger-prototype.apk)。同签名覆盖 0.2.7，不卸载或清数据，最低 Android 8.0。

支付主证据仍按明确成功和实付金额判断。平台通知只作辅助，不单独计支出；共同支付渠道交易号且金额一致时可补缺失平台。平台先到、支付后到只记一笔；普通订单号不能冒充支付交易号，同额不同支付不合并，不改用户编辑。来源与渠道开关共同约束保存，无共同支付身份时保留待核对，不能只凭金额和时间猜关联。

JVM 107 项、Python 10 项、构建和 Lint 通过。源码 API 26 实际执行 54 项，API 35 / 36 各 55 项通过；准确签名 APK 的 55 项及公开旧版重启、code9→10 覆盖保留检查通过。公开下载与被测包逐字节一致，完整证据见 [本版交付记录](docs/RELEASE_0.3.0.md)。识别和存储不联网，没有增加权限、截图、Root 或短信读取；OCR、账单导入以及完整分类/统计/退款/加密备份尚未实现。下一步独立推进离线中文 OCR 与账单文件补漏，保持手机本地处理，先验证模型和读取边界，再恢复实机适配。

本版与第一阶段 `.preview` 应用并列安装。当前缺少完整分类规则、周期统计、退款关联、账单导入导出及加密备份，请保留其他账目来源，不作为唯一账本。

历史：[第一阶段安装预览](https://github.com/xiaochuan45/auto-ledger-android/releases/tag/preview-38843855896-1) 仅验证安装与启动，用户已反馈在一加 Ace 5 正常；它没有自动记账功能，详见 [第一阶段记录](docs/PHASE1_STATUS.md)。

## 自动记账如何触发

以下说明适用于第二阶段小样。采集默认关闭；用户在设置里一次开启自动记账总开关和所需的微信/支付宝渠道开关，按引导授予通知使用权并启用无障碍服务。平台通知需另行选择，默认关闭。之后系统出现受支持的交易通知或付款页面事件时，由对应服务进行本地识别；网页和平台辅助通知新记录仍需核对，确认前不计入支出；无需让账单应用界面一直开着，也不会循环读屏。

离开账本界面不等于清理后台或强行停止。系统需要允许相关服务后台运行；强停、撤销权限或厂商省电限制可能导致中断，应用不能保证绕过。已授权但未连接时，可到设置点“尝试恢复通知监听”，以实际连接回调为准。没有可读取的付款页面或交易通知时无法捕获，当前可手动补记，账单文件导入将在后续实现。后台扣费及不同支付应用版本的覆盖范围需逐项真机验证。

## 产品边界

- 识别、分类和存储在手机本地完成，不需要后端，不使用云端大模型。
- 应用不申请联网权限，不接广告、统计或云端日志；交付前检查最终 APK。
- 消费平台、支付渠道和消费分类分别记录；未知信息不编造。
- 付款成功且实付金额明确才自动入账；金额或状态不明进入待核对。
- 交易通知、无障碍页面等来源的覆盖能力以实机验证为准；没有可读来源时提供导入或补记办法。
- 云端开发和测试只使用虚构、脱敏数据，真实账单不提交到仓库。

## 开发方向

原生 Kotlin、Jetpack Compose，已使用 Room 本地存储账单。使用 Gradle Wrapper 和 GitHub Actions 在云端编译，不依赖个人电脑。

先走通「云端构建 → APK 下载 → 手机安装启动」，再交付自动识别小样，随后依据真机结果完善功能。每轮明确区分「代码已实现」「模拟或自动化测试通过」「用户手机真机实测通过」。
